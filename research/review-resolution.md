主控对原始调研与设计审查逐条判断后更新最终设计。子报告的严重度和修复建议不是自动采纳的指令。

## 来源与集成复核

| 项目 | 处理 |
|---|---|
| A/B 的原则等于长期、按新覆盖、入口隔离冲突等推断 | 不采用；使用正交属性、范围比对和人工决定 |
| Basic Memory、QMD、OpenViking 的依赖 | 按实际原文记录 SQLite/向量或 embedding 依赖；本项目去除这些部分属于自己的取舍 |
| Mem0 模板存在推断版本与默认策略 | 只引用模板存在；不声称某年某版本正式切换默认行为 |
| PageIndex 建树流程 | 不声称全程无需模型；最终只借鉴领域导航与下钻机制 |
| C 的 Codex 没有 hooks/skill 等价或桌面不支持 | 官方 hooks、skills、changelog 原文已纠正；安装端到端仍待后续开发验证 |
| E 把 notify 字段写成 hook 公共字段 | 主控读取下载的 Hooks 原文，最终使用 session_id、transcript_path、cwd、hook_event_name、model 与 prompt/turn_id 的分层字段 |
| C/E 对八爪鱼 agents API 的判断 | 该集成方向已被用户明确排除；仅保留为历史调研，不构成当前项目方案 |

| E 称 CLI help 快照已保存 | 实际未找到所称 txt 文件；文档不以它们作本地文件证据。CLI 产品结论由已保存官方文档支撑 |
| happy-bridge task-callback 等于 Telegram callback_query | 不采用；当前项目改为自身独立 Telegram 适配，不依赖该桥接服务 |

## F 的设计审查处理

| 编号 | 主控判断 | 文档处理 |
|---|---|---|
| F01 采集游标与消费状态 | 初稿已经规定提交后才归档，未证明真实双写错误；仍值得澄清 | 明确 collector 只管已复制，manifest 唯一决定已消费；归档是提交后可重试清理，不谎称跨文件事务 |
| F02 同批候选冲突 | 接受 | 日整理增加同批候选之间比对，避免两条新矛盾要求同时 active |
| F03 推理缓存过期 | 接受并具体化输入定义 | 缓存含已有记忆集合版本、base commit、taxonomy/scope；提交时再校验 |
| F04 必备约束超预算 | 接受缺失的优先级规则 | 必备优先、冲突单独元数据、required_constraints_complete=false、优先分页；不静默提高预算 |
| F05 分类改变适用范围 | 初稿已要求任何范围变化确认，补充可执行 gate | 所有 reparent/split/merge 计算 effective_scope_diff，非空需确认，不限跨根 |
| F06 跨连接器幂等键 | 不采纳为错误。传输幂等不等于语义去重，截图不压缩也不等于保持尺寸 | 保留独立来源，语义比对判等；补充真实镜像来源 lineage 去重，不对近似句强制合并/提问 |
| F07 相反决策顺序 | 接受需明确规则，不采纳“客户端点击时间最后者赢” | proposal revision CAS，第一个有效提交的终结决定生效；旧按钮拒绝，新更正另建提案 |
| F08 备份恢复防复活 | 接受 | 独立删除清单不随 HEAD 回滚，备份更新删除清单，恢复先应用，缺失最新清单时隔离检查 |
| F09 effective 每日膨胀 | 初稿未要求按每天展开，但需要明确 | effective 只索引有效期边界，as-of 走区间过滤 |
| F10 领域摘要跨项目混用 | 接受 | 先过滤原子成员再生成/选择摘要；scope/filter fingerprint 与成员版本进入摘要 key |

## 较早修订记录

2026-10-08 按用户要求删除现行方案对外部中控的依赖，改为独立 CLI、后台 worker 和 Telegram 适配；去除统计检索、倒排分片和排名融合，改为文本索引导航、关键词/别名查找及可选模型重排。架构图、数据布局、流程、模型接口、开发阶段和验收项目同步更新。原始研究工件保留为历史记录，不构成现行开发要求。

## 最新补充设计

用户随后明确 session 扫描→事件队列→约 5 轮小批处理，并允许查询时 BM25、SQLite 状态记录，要求脚本接口、开发工作包、审计 UI 与代码目录。当前设计据此重写了采集和持久化分工：内容文件为权威，SQLite 管理游标/队列/审计，跨介质发布使用 intent 恢复。原 query 保留及改写漂移约束、UI 审计 DTO 与 17 个开发工作包均已补齐。前述“全面排除统计检索”和“运行状态纯文件”属于已被后续需求替换的历史。
