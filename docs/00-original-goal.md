## 用户原始陈述

我想设计一个离线的Memory的Agent。它主要做的事情是每天接入系统中不同的Agent入口，这些入口可能是Claude Code，可能是可能是可能是Code X，或者其他的这个Honey。它干的事情就是记录记忆、召回记忆、整理记忆。记录记忆和召回记忆都是通过一点点入口来的，那可能是需要一个hook或者关键词触发，尤其召回记忆需要关键词触发，正常不需要触发。然后整理记忆是一个比较复杂的一个。或者说比较想用Agent去实现的一个东西。首先基本的记录记忆就是把用户提到的要求，提取出它适用的范围。具体的要求分清楚是细节的要求还是原则的要求，然后把它们放在合适的归类的部分。那记忆有几套索引，一套索引是按日期，一套索引是按语义，就是按领域啊、Tag呀、具体的项目啊，这样的细分下去，就是语义。切分，这样两套索引，这两套索引走文本。然后有一个整理记忆，整理记忆呢，就是在每天晚上凌晨的时候，发现如果有增量的信息进来，那就去跟之前做的记忆进行对照。然后如果是同一个领域、同一类的要求有冲突，就要么去找人确认，就是发消息，一般是Telegram的方式去确认是不是要覆盖啊？还是要保持原来的啊？还是怎么样？另外一个，如果没有冲突，那就做直接记忆。按照原则和细节，有些是短期的信息，有些是长期的信息，啊，这样去分类，有些是用户的信息，用户自己的画像，有些是用户对于代码的要求，有些是用户对于比如说多媒体的要求，或者说是搜索信息的要求等等这些不同领域的方式。然后这个整理记忆呢，也应该就是中等周期，比如说周级别或者月级别去review它的这个分类是不是成功的。通过这样的方式来动态地整理这些领域和浓缩这些记忆信息。根据我这个的要求，记录一个我这个属于一个新的项目，在当前文件夹下造一个不同子文件夹，然后记录我这个是一个Memory Agent的一个开发的一个原始目标。然后你去根据相关的要求去搜索现在社区里面已经有了的实现范式。然后结合这些实现机制去推导出来我们开发这个项目整体的一个架构，具体的技术使用，然后一些基本的边界和设计。然后这个细分领域的搜索，你可以通过Claude Code去做。它的成本比较低，你可以搜得细致一些。因为Memory是一个大家都很研究很多的领域，虽然没有成熟，但是我希望结合我的要求，能够做出一个相对能用的产品。我个人用的一个产品。然后呢，整体的要求就是一个记录的时候，结合各Agent入口的上下文去做的记录。然后有多套索引，方便各种方式的查询。然后有这个整理是分层去做整理，按领域项目还有长期短期，还有这个细分领域，比如说AI相关的使用，有AI Coding的，有AI画图的，有AI生成视频的，有各种这样的领域，它要方便扩展，也要方便它聚合，要有合适的这个档位。那这个抽象的层级需要有一些参考的案例，那希望能在社区里面找到合适的案例。这些都是关键的设计。然后他也是利用这个离线的方式，就是不是实时在Agent里面去做操作，所以他对时效性要求不高。然后他尽可能要走文件，这样对索引的底层要求也不高，尽量不要用ES或向量DB，这样容易让这个项目复杂度变高，就只用文件。然后当前的任务的目标主要是完成这个设计，项目的设计。去找到合适的索引的具体方法啊、分类的具体方法啊，然后一些基本的架构啊，一些跟Agent入口打交道的方式啊，还有一些跟这个大模型交互的这个中间件，比如说要做一些总结，要做一些召回的时候，需要大模型做一些排序，或者说总结，需要有一个Agent的路由啊，等等等等，这些各模块，一设计好层级，设计好一个架构图，然后递推出这个开发的整个设计的文档。有什么不确定的问题及时问我。先不要做开发，调研的部分要用claude code subagent去做。

## 从原文直接提炼的约束

- 个人使用，跨 Agent 入口，记录时保留必要上下文。
- 记录、召回、整理分离；召回必须显式触发，不向普通会话默认注入记忆。
- 日期索引与语义索引均为文本；使用文件，避免 ES 和向量数据库。
- 区分适用范围、原则与细节、长期与短期、个人画像与不同工作领域。
- 每日增量整理；冲突进入人工决策，主要通过 Telegram。
- 周或月进行分类复查、领域聚合、记忆浓缩。
- 必须参考社区实现，尤其是分类层级与文件索引方法。
- 调研使用 Claude Code subagent；当前阶段只交付设计。

## 待澄清项

1. 离线指后台异步，还是模型也必须完全本地运行。
2. 默认记录采用自动提取明确要求，还是仅显式“记住”。
3. “Honey”入口的准确产品名称及首版范围。
