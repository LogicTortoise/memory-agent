# Memory Agent 需求与边界

设计日期为 2026-10-08，默认时区为 Asia/Shanghai。目标是一个个人使用、以文件为基础、能跨 Agent 入口工作的记忆产品。它记录可追溯的用户要求，按需召回，并在后台整理分类与解决冲突。

## 已确认的产品行为

用户明确确认了以下要求：

1. 离线指后台异步处理，允许调用 Claude Code 和云端模型。
2. 默认自动提取用户明确表达的要求；显式“记住”作为补充。
3. 首版覆盖 Claude Code 和 Codex；其他入口以后通过统一协议接入。
4. Memory Agent 是独立项目，不依赖八爪鱼或其他个人中控服务。
5. 最新补充允许 BM25 仅在查询阶段使用；要做好 query 改写、扩写和原始约束保留。
6. 自动采集通过扫描本地 session 文件的新增内容完成，事件排队后按连续对话小批处理，默认每批 5 轮、可配置 10 轮，并受 token 限制。
7. 提供外部脚本可调用的完整接口、确定的开发工作包和目录结构设计。
8. 增加审计 UI 的布局、主题与数据设计；SQLite 可保存游标、任务、队列、审计等细碎状态。

[原始陈述](00-original-goal.md)保留用户原话。本设计中的技术参数属于建议默认值，不能被误当成用户已经表达的偏好。

## 功能需求与验收映射

| 编号 | 需求 | 应有行为 |
|---|---|---|
| R01 | 保存入口上下文 | 从本地 session 增量读取用户要求及必要上下文、会话/消息/分支/位置和来源时间；可回到原话 |
| R02 | 自动记录明确要求 | 抽取对象是用户的要求、偏好和自述事实；助手建议、引用与检索内容不能自动变成用户记忆 |
| R03 | 显式召回 | 用户调用命令或约定关键词才查询；普通会话不注入记忆摘要 |
| R04 | 双文本索引 | 按日期与按领域、项目、标签查找同一条权威记忆，索引可重建 |
| R05 | 多维分类 | 范围、内容类别、原则与细节、期限、领域、项目、标签相互独立 |
| R06 | 每日增量整理 | 有新增事件才抽取与比对；重复运行不重复写入，无新增不消耗模型 |
| R07 | 冲突人工决策 | 真正冲突进入确认队列，Telegram 支持比较和选择；未回复不默认覆盖 |
| R08 | 中周期重整 | 周级检查细分与合并建议，月级检查摘要和分类质量，避免丢失原子证据 |
| R09 | 文件存储 | 记忆和证据仍走文件；SQLite 记录运行状态与审计；不用 ES/向量 DB；BM25 仅查询时计算 |
| R10 | 模型路由 | 抽取、冲突判断、分类重整、重排/总结各有明确输入输出、预算、超时和失败处理 |
| R11 | 可扩展入口 | 新入口只转换统一事件，不复制记忆核心逻辑 |
| R12 | 可运营 | 任务幂等、可追溯、可恢复、可删除、能知道积压与失败；由项目自身管理调度、任务状态和通知 |
| R13 | 当前交付范围 | 完成调研、架构、数据协议、边界、阶段与验收设计；没有产品实现 |
| R14 | session 扫描 | 增量游标、续写/轮转/半行、源修订、backfill 与恢复边界明确 |
| R15 | 小批模型处理 | 默认 5 轮，轮数/token 双限制，工具不计轮、跨批次上下文可追溯 |
| R16 | 脚本接口 | 同步/异步、JSON 输入输出、退出码、幂等、取消/重试明确 |
| R17 | 审计 UI | 批次与证据、冲突、query 轨迹、状态/游标可查，布局/主题已设计 |
| R18 | SQLite 状态 | 单一游标/队列/审计存储，文件与 DB 发布有崩溃恢复协议 |
| R19 | 开发边界 | 每包输入、输出、拥有目录、依赖、技术与验收确定 |

## 首版使用场景

- 在 Claude Code 说“以后做 bugfix 不保留旧兼容代码”，后台保存为 coding 领域的长期原则，并保留原话来源。
- 在某项目说“这次修复仍兼容旧配置”，识别为项目/任务范围的局部细节；不能直接把全局原则覆盖掉，也不能假定二者一定可以并存。
- 显式要求“回忆一下我对 AI 画图的要求”，返回相关领域与上位范围的有效记忆、原话引用和待决冲突。
- 凌晨新增要求与已有要求不一致，收到一条可比较的新旧内容确认；不回复就保留待决状态。
- 周或月发现 AI 视频记忆增多，建议从 AI 媒体生成细分为图片与视频；旧链接与历史来源仍可访问。

示例是设计测试情景，不自动写入真实用户记忆。

## 产品边界

不自动回填整个历史会话库，不把所有聊天变成记忆，不在未触发的普通会话中加载记忆，不让模型直接覆盖权威文件。资料库、网页收藏和向量知识库不属于首版的记忆主体。

个人画像只记录用户明确表达且有用的自述。助手推测的性格、健康或身份属性不进入确认事实。项目临时指令不自动升级为全局偏好；反复出现也只增加证据，不自动扩大适用范围。

当前任务不安装 hook、不启动守护进程、不注册定时任务、不配置 Telegram、不发送消息、不提交或推送 Git。设计中的这些步骤属于后续开发阶段。

## 基础设施约束

本项目独立安装、配置、启动和运行。核心提供 CLI 与后台 worker，自行管理定时、重试、进度和 Telegram 决策通道；操作系统服务管理器只负责进程启动与退出后的恢复。用户对本项目的明确要求优先于本机已有的通用基础设施约定。

公共目录现有私人记忆应视为未来可选择导入的资料源，不在本轮修改、迁移或同步。新项目目录为 `/Users/Hht/Documents/Default Project/memory-agent`。
